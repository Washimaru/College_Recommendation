# UniMatch UI — Design

**Date:** 2026-07-27
**Sub-project:** B — Next.js frontend
**Depends on:** `2026-07-27-real-university-catalog-design.md` (contract v2.0.0)
**Status:** design, awaiting approval

## Goal

A working web UI for the pipeline: a student fills in a profile, gets a ranked
list of real universities with reasons. This is the first time the system is
visible to a non-developer.

Success: `npm run dev`, fill the form, see ranked real schools with rationales
and honest data badges.

## Context

The previous Next.js frontend (`college-recommender/`) was lost and is
unrecoverable — no git history, no snapshots, no backups. This is a rebuild, not
a repair. The one asset that survives is the earlier static UniMatch site at
`~/Claude/Projects/University_Recommendation_Project/`, whose form structure,
slider labels, and Reach/Target/Safety concept are worth inheriting even though
its code is a different stack.

## The gap this spec closes

`RecommendationResponse.results[]` currently carries only:

```
{ university_id, name, score, rationale }
```

That is enough to render a list and nothing more. A college-search tool has to
show *why* a school is on the list and what it costs — and the two features
inherited from the original both need data that isn't there:

- **Reach / Target / Safety** needs the school's `avg_gpa` to compare against the
  student's.
- **Provenance badges** ("est." vs verified) need the `provenance` object, which
  is the whole point of the honest-nulls model in sub-project A. Without it, an
  editorial estimate and a federal statistic look identical on screen.

So B is **not** purely client work: it requires extending `Result`.

### Contract change — `recommendation.schema.json` v1.0.0 → v2.0.0

`Result` gains a compact `university` summary and a server-computed tier:

```
university_id  string
name           string
score          number 0..1
rationale      string
admit_tier     "reach" | "target" | "safety" | null      NEW
university     object                                     NEW
  avg_gpa          number
  avg_sat          int | null
  acceptance_rate  number | null
  net_price        number | null
  enrollment       int | null
  size             enum
  location         string
  country          string
  provenance       object
```

Mirrors to update in the same change: both Python `schemas.py` and
`services/gateway/src/types.ts`.

**`admit_tier` is computed server-side**, in `recommendation-service`, not in the
browser. It is deterministic domain logic and belongs with the rest of it:
with `d = university.avg_gpa - profile.gpa`:

```
d >=  0.12  -> "reach"    # school's admitted average is above the student
d <= -0.12  -> "safety"   # student is above the school's admitted average
otherwise   -> "target"
```

**null when `profile.gpa` is absent.** Thresholds inherited verbatim from the
original project's `admitTier`. Putting it in the client would make it
untestable by the existing gates and duplicate it for any future consumer.

## Stack

Next.js (App Router) + TypeScript + Tailwind, in `college-recommender/`,
reclaiming the directory the old app occupied. React 19 / Next 16, matching what
the previous app used.

No component library in v1. The UI is one form and one results list; shadcn or
similar is weight without payoff at this size, and the previous app's dependency
set is exactly what we cannot verify anymore.

## Structure

```
college-recommender/
  app/
    page.tsx              the form
    results/page.tsx      ranked results
    api/recommend/route.ts  server-side proxy to the gateway
  lib/
    contract.ts           types mirroring docs/contracts (single source)
    tiers.ts              badge/label helpers (presentation only)
  components/
    ProfileForm.tsx  CultureSliders.tsx  ResultCard.tsx  ProvenanceBadge.tsx
```

**The API route is a server-side proxy, not a direct browser fetch.** Three
reasons: it keeps `GATEWAY_URL` server-side so the gateway is never exposed to
the browser, it avoids adding CORS to a gateway that currently has none, and it
gives one place to shape errors. This mirrors what the lost app did with
`/api/recommend`.

## The form

| Field | Control | Contract path |
|---|---|---|
| GPA | number, 0–4.0 | `profile.gpa` (required) |
| SAT | number, 400–1600, optional | `profile.sat` |
| Intended major | select | `profile.intended_major` (required) |
| Max net price | number | `profile.preferences.max_tuition` |
| Preferred size | small/medium/large/any | `profile.preferences.preferred_size` |
| Locations | multi-select | `profile.preferences.locations` |
| Culture | **6 sliders**, default centred | `profile.culture_prefs` |

Slider labels are inherited verbatim from the source project (`collab`,
`quirky`, `idealist`, `research`, `spirit`, `seminar` — see spec A).

**There is no MBTI input.** It was dropped by decision; the sliders replace it.

Sliders default to centre, which the scorer reads as indifference (`culture_fit
= 0.5`). A student who touches nothing is not penalised, and the copy should say
so — "drag only the ones you care about" — because a centred slider looks like an
unanswered question otherwise.

`max_tuition` is labelled **"Max net price per year (after aid)"**, since spec A
established that the underlying figure is net cost, not sticker tuition. The
field is renamed to `max_net_price` here, completing the rename spec A deferred.

## Results

One card per school: name, location, score, `rationale`, the `admit_tier` badge,
and the key stats — acceptance rate, net price, enrollment, size.

Every numeric stat renders through `ProvenanceBadge`:

| provenance | rendering |
|---|---|
| `observed` | plain value |
| `web_verified` | value + source link |
| `editorial` | value + "est." |
| `not_applicable` | "n/a" + tooltip (e.g. "UK — SAT not used") |
| `absent` | em dash |

This is the visible payoff of the honest-nulls model. **A null must never render
as `0`, "N/A%", or a blank that reads as zero** — that is the failure mode the
whole data design exists to prevent.

Loading state shows the loop is running. Streaming the per-iteration trace over
the WebSocket route is a **stretch goal**, explicitly not v1: the sync endpoint
returns in well under a second against 364 schools, so streaming is a
demonstration of the architecture rather than a user need.

## Error handling

- **Validation** — client-side against the same zod shapes as `contract.ts`,
  with the gateway's 400 as the real gate. Field-level messages, no silent drops.
- **Gateway unreachable / 502** — an explicit "recommendation service is
  unavailable" state with a retry, not an empty results list. An empty list and a
  failure must never look the same.
- **Zero results** — reachable via Layer-1-style constraints (e.g. a budget no
  school meets). Distinct copy suggesting which constraint to relax.
- **Partial data** — a school missing `acceptance_rate` still renders; the stat
  shows its provenance state. Missing data never blocks a card.

## Testing

Vitest + React Testing Library, offline, mirroring the gateway's setup.

- **Form → payload** — a filled form produces a body that validates against
  `profile.schema.json` v2.0.0; centred sliders produce `culture_prefs` of all
  `0.5`.
- **No MBTI** — the rendered form contains no MBTI control (guards against
  reintroduction).
- **Provenance rendering** — each of the five states renders distinctly; asserts
  a null never renders as `0` or an empty numeric.
- **`admit_tier` badges** — reach/target/safety/null each render correctly.
- **Error states** — 502, validation failure, and zero-results each render their
  own distinct state.
- **Proxy route** — forwards to `GATEWAY_URL` and maps upstream failure to a
  handled error, with `fetch` mocked. No live gateway in unit tests.

Coverage floor 70%, matching the gateway.

## Out of scope

- WebSocket streaming (stretch).
- Favourites, compare tray, detail modals, Explore charts — the source project
  has all four; they are a second iteration, not v1.
- Authentication, persistence, saved profiles.
- Mobile-specific layout beyond what Tailwind's responsive defaults give.

## Open decisions

1. **Where the major list comes from.** The form needs a canonical list. Options:
   derive from the distinct `majors` across the 364 schools (guarantees every
   option matches something), or reuse the source project's `majors.js`.
   *Recommendation: derive from the catalog*, so no option can return zero
   results by construction.
2. **Whether `college-recommender/` should be a nested git repo.** It previously
   had its own `.git`, which is how its history was lost when the directory was
   removed. *Recommendation: no* — keep it inside the root repo now that one
   exists, so it is covered by the same history.
